# Delta：推理与证据

> 本文是 Delta 设计记录的正式文本。同步自 Qoder 记忆条目 `project-delta`（脚本 `tools/sync-from-memory.sh`，最近同步 2026-11-08）。


Delta is the planned second branch / new application (design discussed 2026-11-07; **code started 2026-11-08 with the byte layer, `crates/delta-term`**, after the first attempt was cleared at the user's request). It is not a terminal with an AI panel: it is an **ADE where humans and agents are both clients of one control plane**.

**Status roll-up lives in [project-delta-status](status-rollup.md) — read that first for what is decided vs proposed vs open (compiled 2026-11-08 after I twice fabricated attribution). This file holds the reasoning and evidence; if the two disagree on status, the roll-up wins.**

**The frame that outranks the labels (user, 2026-11-08): *"与其说他是ide,ade，请记住他还是个AI终端，这才是最珍贵的。"*** Delta is an **AI terminal**, and the IDE/ADE descriptions are things it also is, not the frame it is judged by. **The noun is the English word: *"说错了，我们不是AI终端，而是AI terminal"*** — deliberate, because Chinese 终端 blurs terminal / console / shell, while **terminal names one layer precisely: the PTY pair plus the escape-sequence device contract**. What that choice commits us to, and the two facts checked on 2026-11-08 that came with it:
- **"AI" is a modifier on what runs inside, not on what the product is.** So the byte layer stays neutral and replaceable (existing law), and agents are processes in it. Crucially, *terminal* here still does **not** mean we ship a shell — the in-app-shell idea was rejected the same day (see below), so terminal = emulator + host, not prompt.
- **Byte-stream fidelity becomes the identity, not a feature, which makes conformance a testable acceptance bar with a real, carryable corpus**: [vttest](https://invisible-island.net/vttest/) (VT100/VT220/VT420 + xterm, display *and* keyboard), [esctest2](https://github.com/ThomasDickey/esctest2) (Dickey's automatic unit tests for emulator control-sequence behaviour), the authoritative sequence reference [xterm control sequences](https://www.xfree86.org/current/ctlseqs.html), and [xterm.js's supported-sequence list](http://xtermjs.org/docs/api/vtfeatures/) as one emulator's self-declared coverage. Per 记忆条目 feedback-no-stitched-dependencies，本目录未收录，规则见 ../AGENTS.md and 记忆条目 project-kite-strategy，本目录未收录，规则见 ../AGENTS.md, these are vendored-as-reference and their tests carried, not depended on.
- **The IME/composition problem is reclassified by this name**: it is no longer "the hardest subproblem" but *"if it is broken, we are not the product"* — a terminal that mis-renders composition is not a partially-finished terminal.
- **Naming collision the user has NOT yet ruled on**: Warp's public positioning was literally **"AI terminal"** and then moved to **"the Agentic Development Environment"** with the tagline *"Not a terminal, not an IDE"* ([Warp blog, 2025-06-24](https://www.warp.dev/blog/reimagining-coding-agentic-development-environment); third-party 2026 reviews describe Warp 2.0 as open-source with parallel Claude Code/Codex/Gemini — unverified, do not treat as fact). So (a) our **ADE** acronym reads near-identical to Warp's *"Agentic Development Environment"*, and (b) choosing **"AI terminal"** in 2026 means choosing the word the biggest player publicly walked away from. Not a problem — it is a *technical* commitment rather than a marketing one (Warp left the byte stream behind for its own block-oriented input UI), but it must be a stated position, and the ADE name may deserve replacing. **The user's call, flagged not decided.** → **CLOSED the same day: *"我们叫Delta。不用管别人叫我们什么"*** — the name is Delta and neither "ADE" nor "AI terminal" is a positioning claim we owe anyone, so the Warp collision above is recorded only as provenance for why the label question was raised ([project-delta-status](status-rollup.md) item 27).
**Consequences the user accepted with the frame (written before the noun was tightened, and still standing):**
- **The spine object is the pane-with-a-process in it, not the file-with-an-editor.** File tree, tabs, groups are guests. Files are reached by *command* — which is what `kkk <file>` in kite's shell already proved ([shell.rs:49](file:///E:/Think/crates/kite-app/src/shell.rs#L49), [:1687](file:///E:/Think/crates/kite-app/src/shell.rs#L1687), emitted from the tree at [sidebar.rs:92](file:///E:/Think/crates/kite-app/src/sidebar.rs#L92)) and what the "editor is a first-class terminal command" asset meant. This is a **partial answer to the sidebar contest** (see [project-delta-status](status-rollup.md)): the permanent strip is closer to `jobs` than to a kanban.
- **Agents are processes, so the terminal's existing verbs are the agent API**: focus, read, send-text, send-keys, wait-output, process-info, close, rename, zoom, swap (all verified in herdr's `pane` surface — and note **`wait-for-exit` is ACP's `terminal/wait_for_exit`, not a herdr verb**: herdr waits on *output* with `pane wait-output` and queries liveness separately with `pane process-info`, which is the shape our pin needs, since it counts event rows and process state, not a text match). herdr's `pane report-agent --state` is an agent reporting *through the terminal*, which is the precedent that this frame is already the shape of the strongest tool in the pool (herdr self-describes as a "terminal workspace manager for coding agents").
- **Admission cost stays zero, and non-ACP agents are programs, not second-class citizens.** ACP-speaking agents give us the write path; TUI-only agents are still observable the way the terminal observes everything. Under an IDE frame that's a degraded mode; under a terminal frame it's the normal state of a shell. This is where kite's terminal semantics — the control-byte rules ([feedback-terminal-control-bytes](../carried-semantics/terminal-control-bytes.md)), Ctrl+C ([feedback-shell-ctrl-c](../carried-semantics/shell-ctrl-c.md)), bare-exe resolution ([feedback-shell-cmd-semantics](../carried-semantics/shell-cmd-semantics.md)) — pay off as carried *semantics*, which the "no kite code reuse" ban never touched.
- **It strengthens the open sandbox question rather than weakening it**: in a terminal, the permission model has always been the *account*, not the app's settings panel (`su`, run-as, ACL). So "is unreadable real" and "does the agent bypass our fs methods" get a stronger yes under this frame — the jail is OS identity, and it works against any program, which is the only enforcement that is honest in a terminal.
- **Reference pool now has two camps and the frame picks the adjudicator**: terminal-native (tmux, herdr, alacritty, Windows Terminal, kite's shell) vs IDE-native (VS Code, Zed, Fresh, helix). When two precedents disagree, the terminal camp wins by default; deviations must be argued, not assumed.
- **What the frame does NOT change**: "not a terminal with an AI panel; humans and agents are both clients of one control plane" — the terminal frame is that same claim spoken in terminal vocabulary, and it sharpens it. Layout law, ACP-host-never-agent-author, the ballot rules and 项目=工作区 all stand. **One item in that older list is no longer standing: the close-kills-process law was superseded the same day by 任务优先 ([project-window-ownership](window-ownership.md) law 1, [project-delta-status](status-rollup.md) item 5).**
- **The one place the two frames genuinely point opposite ways, still the user's call**: a terminal says *text streams are the truth and structure is derived*; the ledger design says *structure is the persistent fact and text is its projection*. My proposed reconciliation — **structure is the storage truth (scrollback is lossy and unaddressable, so authority and audit cannot live there), commands are the interaction door (every persistent fact must be reachable and creatable by a typed command)** — is labelled as my proposal, not adopted.

**The component list as the user cut it (2026-11-08), plus what reading kite added.** *"我们目前有几个重要的组件"*: **(1)** 分屏 / 标签 / 工作区 / 状态展示 chrome; **(2)** 自有编辑器 — named **`miku`** on 2026-11-08 (*"编辑器的话叫miku"*) — a usable minimal vim (discussed before), and *"甚至随时移交AI来辅助"* i.e. window ownership; **(3)** 权限门控 + 自有数据库 + git; **(4)** 群聊 + AI 协同 (email removed, see below); and the one he then insisted on — *"还有别忘了我们自己的shell"*, now named **`solid`** (*"shell的话叫solid"*), **bash-shaped but not bash**, only basic builtins (`cp md cd ls pwd` + 等等), and **`$` / `@` and that class of symbols are reserved for delta's own syntax, never consumed by the shell** ([project-window-ownership](window-ownership.md) law 25). So the shell is **its own component, not part of chrome**.
**And the chrome object model was cut the same day** ([project-window-ownership](window-ownership.md) laws 21–23): the **调度器 + 每个 AI 的实时流式信息是同一个窗口**（点 AI 就是它，那里关闭最好用）, the **群聊也是一个窗口**（在那里也能关 AI 任务，而群聊关闭就是 AI 关闭）, and **软件里没有"工作区"这一层** — 工作区只是群聊打开时选定的根路径. This is what ended the sidebar contest and the "where does the group live" question, and it confirms the direction my item-38 argument pointed at: scope root = ACP `session/new`'s `cwd` + `additionalDirectories`, address = group/AI/session.
**Which of these is 基本盘, decided 2026-11-08**: components 1, 2, 4 and the shell are the base to build first; **component 3 (权限门控 + 自有数据库 + git + 备份) is left as a blank slot and done later** (*"另外数据库，git，备份权限管理，留好空白。以后再做。先做基本盘/现在权限先防空"*). Note that **(4) 群聊 is not an add-on and must never be dropped from a scope answer** — the group is where a window is handed to an AI (*"在群组中@他，他开始执行"*), where an AI is told it may leave `share` (*"你在群组跟他说好了，他就会立刻切换为agent模式"*), where questions and ballots live ([project-group-decision-rules](group-decision-rules.md)), and it is the container itself (*"一个工作空间就是一个群"*). I once answered "what is still missing" down the window-law chain and left 群聊 out entirely; the correction is to walk **this list item by item** — see 记忆条目 feedback-component-checklist-not-law-chain，本目录未收录，规则见 ../AGENTS.md.

**Why the shell is the load-bearing one — but NOT for the reason I first gave, and the kite precedent I cited is REJECTED.** On 2026-11-08, right after I pointed at kite's sidebar composing `cd` / `kkk` ([sidebar.rs:84-93](file:///E:/Think/crates/kite-app/src/sidebar.rs#L84-L93)) as the seed to generalize, the user cut it off: *"不不不把，不要再研究kite了，我明确说，kite的这个不可取，我们要做的绝对不是这个"*. So **kite's in-app-shell-and-chip-types-into-it pattern is explicitly not the model**, and the "verb table lives in delta's own shell" reasoning that leaned on it is withdrawn (see [project-delta-status](status-rollup.md) 1.24). Do not mine kite for design precedent any more — neither its shell nor its sidebar mechanics.

**The contradiction the user's rejection exposes, and it favours them.** An existing law says the terminal is a neutral byte layer and **the shell is a replaceable program: cmd and pwsh are first-class profiles, never emulated or forwarded** — yet my proposal made delta ship its own shell as the control plane's syntax, which is exactly *emulating a shell*. My litmus law ("anything not doable from the shell is a widget") inherits the rejection too, and is re-stated without a shell: **any affordance that cannot be reached from the command table is a widget, not a feature** — the door is the verb table, not a prompt inside the app.

**The alternative shape, which is where the discussion actually stands: the verbs live in an outside CLI that drives the app, not in an internal shell.** All three precedents worth studying are of this kind and none of them is kite: tmux (`tmux <cmd>` against a server), herdr (`herdr workspace list|create|close`, `herdr pane focus|send-keys|wait-output|…`), Fresh (`fresh --skill` script verbs). What that shape buys, concretely: the user keeps whatever shell they already like in a pane and we emulate nothing; the same textual verb table serves humans, scripts and agents (delta is an MCP server, so the agent-facing tool list and the CLI are one surface rather than two maintained ones); line editing, completion, history, prompt cosmetics and the whole ConPTY/IME burden stay somebody else's problem, which is where kite's cost actually went; and headlessness stops being an aspiration because the CLI *is* the headless interface. What it does NOT settle: whether delta still offers a small built-in command line for app verbs (discoverability, and "what can I even ask for" — palette vs `--help`), and how the old wins are re-expressed (no `kkk` needed — `open <file>` from any shell puts a file in a pane, same capability, different mechanism).

**Foundation principles (not negotiable):**
- Terminal = neutral byte layer (ConPTY, grid, key encoding). Shell = replaceable program; cmd and pwsh are first-class profiles, never emulated or forwarded.
- Core = control plane: typed commands, derived structured state, ordered event log. Headless operation is required: everything an agent can do must work without a window.
- No screenshots as the primary channel: give AI bounded, derived, delta-based views of terminal/editor/pane state.
- Three clocks separated: execution (atomic semantic actions), presentation (reveal overlay, caret trail, per-pane follow-scroll), rendering (damage-driven frames). Presentation is a projection of committed state and snaps to final on human interaction.
- Human and AI are equal in visibility and expression, not in privilege: only humans grant/revoke leases, approve destructive work, and set retention/GC policy.

**Modes and leases:** one lease per pane carrying write / advise / observe / auto-approve, so modes are switches rather than an enum — *Driver* (AI holds the pane, human keystrokes go to an instruction composer) and *Advisor* (human types normally, AI only annotates, and advice must never move the human's caret, scroll or focus). Leases are granted per turn and auto-returned, handoff happens only by explicit action, and seizing a pane cancels only that pane's in-flight action. Backup classes are derived by rule: an agent may not set its own class and downgrading one needs a human.
**This paragraph is the 2026-11-07 version and three of its claims were revised on 2026-11-08; [project-window-ownership](window-ownership.md) laws 4 and 13–18 win wherever they disagree.** (a) **"modes are switches"** — the user's final shape is a **mode enum in four chrome states (`normal/insert/replace/agent`) plus `share`**, default `normal`, with **input modes attached to the keyboard and ownership modes attached to the window**; the lease kinds below survive as the *authority* record, but they are no longer the thing the user sees or presses. (b) **"handoff happens only by explicit action"** — now: **no application for an untouched window, an application for one the human modified**, consent auto-saving and entering `agent` (law 4); and *if a window exists, the AI takes it over* (law 3). (c) **"the AI holds the pane, human keystrokes go to an instruction composer"** — reversed by law 18: in `agent` the human **keeps sight and loses the keyboard** (they are a viewer, not a composer), and the composer-like state is `share`, where they *can* type and the AI reads it live. `Advisor` survives unchanged in substance: law 18's audience rule and the existing "advice never moves caret/scroll/focus" prohibition are the same law stated twice.

**Actors and messaging:** everyone (human, local agent, remote email) is one actor row with a mailbox; instructions, advice, approvals and notifications are one message type carrying context references. Peer agents may only *ask*, never command or grant. Agents exchange references into the ledger, never copied state. Advice from an agent alone can never justify a write; backing must be a human approval or verifiable execution (tests, compile, exit code). Openness comes from manifests and self-described API schemas, plus prompt-level roles — not hardcoded role code. First version: doer + reviewer + one human, but nothing caps the count.

**History and safety:** an append-only ledger of intent rows (path, note, actor, turn, pre/post hash, revision, class, status) plus a deduplicated chunk store; full and incremental snapshots share one store. Only project files are stored (build output excluded) and the store lives outside any snapshotted tree. Cleanup is periodic, reachability-based, logged as its own event, never on close. No fake-delete/trash: the rule is **backup must succeed before deletion is allowed**, with a per-path retrieve entry point. When the user says 内存 in this discussion they mean local file/disk usage, not RAM; RAM stays bounded by streaming chunking, a bloom filter plus on-disk index, and two-phase GC marking.

**Predecessor: kite/kkk supplies design *and* interaction feel, but not code.** delta does **not** reuse kite/kkk source ("那是狗屎"); it starts a fresh workspace. What IS carried over as design assets, named by the user on 2026-11-07: state management, the comfortable keybinding feel, the built-in-editor idea, sidebar file tree + git integration, top tabs, bottom status bar. The built-in editor's weakness was implementation quality, not the concept — so carry the shape, drop the implementation.

**IDE → ADE is literally about the two panels.** kite's sidebar shows *what is on disk*; herdr's sidebar/status bar/window bar show *what is happening right now* (which pane holds which agent, its lifecycle state, who owns it — all pulled from structured API calls like `pane list`, `pane layout`, `report-agent`, not screen scraping, which is why the whole shape is portable to our control plane). delta needs both, and the open design question the user has not answered: one shared sidebar rail scrolling a file tree and an agent list, or two rails; and which row carries agent status given both apps have a status bar. **The rail half is closed 2026-11-08 by law 23: there is no workspace level in the interface, so there is no workspace/project panel competing for the rail; what remains is only which row carries which fact.**

**Custom Ctrl chords get dropped, and the replacement is herdr's key model, not our own invention** (user: "别用我们的，用他们的"). From herdr's `--default-config`, verified 2026-11-07: (1) two key classes with distinct syntax — `"prefix+n"` requires the prefix, `"ctrl+alt+n"` is a direct terminal-mode shortcut — and it states which chords may be taken at all: *"Most reliable direct bindings are ctrl+letter, function keys, and explicit modified chords."* That sentence is the policy: only those three classes bind directly, everything else lives behind the prefix. (2) **`copy_on_select = true` by default** means mouse selection copies immediately so **Ctrl+C is never stolen from the child**; setting it false retains drag/double-click selection *"until Ctrl+C"*. This supersedes kite's "selection wins, else interrupt" rule for delta — do not carry the old rule forward. (3) **Resizing and navigating are modes with documented precedence**, not global chords: `resize_mode = "prefix+r"` (optional `ctrl+shift+alt+left` to resize without entering the mode), and *"These local shortcuts win while navigate mode is open."* (4) Even the scrollbar column is a setting with its trade-off documented inline: `pane_scrollbars = false` *"reclaim[s] the scrollbar column and keep[s] it out of terminal-native selections."*

**Two Windows-hard problems herdr has already answered — I had wrongly listed them as unowned.** (a) `cursor = "auto|native|drawn"`: auto *draws its own cursor on native Windows builds and WSL to avoid ConPTY cursor flicker, and uses the native terminal cursor elsewhere* — probably what the user means by herdr's "Windows mode". (b) An opt-in flag that while prefix mode is active *temporarily switches the host input source to an ASCII-capable mode so prefix commands register even when an IME is active, then restores the previous input source on exit; on Windows it toggles the IME*. This halves the "IME is the top unowned risk" claim — where the composition string gets drawn is still ours. Also pre-solved landmines worth copying: *"Windows only: allow ordinary same-account clients to control an elevated server"* (the UAC problem our server process will hit) and *"On Windows, command strings run through cmd.exe /d /c"*.

**kite is frozen/archived as of 2026-11-07** — do not propose changes to it; its Ctrl chords therefore only need to be absent from delta, not removed.

**Windows Terminal — demoted from carrier to behavioural baseline.** It will not host our windows, tabs, splits or agent panes (agent-owned panes are impossible to delegate to it), but key byte encodings and observable shell behaviour should *match* it, because users and existing programs already expect that. Note the enabling fact: much of WT's cmd/pwsh behaviour is really ConPTY's translation, which we get for free since we also use ConPTY; WT's own contribution (key tables, edge cases) is a reference oracle to diff against, not a dependency. "Works with every shell" must be defined as testable conformance — VT/xterm private modes, kitty keyboard levels, OSC 133/7 shell-integration contract, per-shell adapters (pwsh via PSReadLine, bash/zsh via preexec/precmd, fish built in, **cmd has no reliable hooks** — a hard boundary WT also hacks around) — captured as a behaviour matrix (shell × feature) validated side by side with WT. See the reference-not-dependency stance below: libghostty-vt is a reference and test corpus, not a link target (the earlier note that ghostty was immature on Windows is superseded — a shipping Windows product statically linked it in July 2026 — but that does not make it right for delta).

**Tabs and splits — tmux is the comparison target.** Must match or consciously beat: session surviving outside the client (detach/attach), break/join/swap-pane, zoom, numbered selection, cross-window pane moves, per-pane independent scrollback and copy-mode, control-mode's line-oriented protocol. Diverge on: pane content read as structured state + reveal overlay instead of screen scraping, and panes carrying an owner with takeover. ~~"no prefix ergonomics (our keymap is ours)"~~ → **withdrawn by *"别用我们的，用他们的"*: keys follow herdr's prefix model ([project-delta-status](status-rollup.md) item 6), and the takeover half is now governed by the mode/ownership laws rather than a bare "one-key takeover" (a window the human never modified is takeable without asking; one they modified needs consent, which auto-saves and enters `agent`).** Architectural consequence that must be decided on day one: ConPTY belongs to the process holding the child, so tmux-style survival requires a server process owning ConPTY while clients only shuttle bytes — same shape as the headless invariant, but impossible to bolt on later. **(This is no longer open: law 1's close-refusal plus "close must not kill" force the PTY onto the session object, and the same conclusion is reached independently by herdr's headless `server` and Fresh's per-directory daemon — see [project-window-ownership](window-ownership.md) derivations.)**

**Reference-not-dependency stance (revised 2026-11-07 after the user rejected 缝合).** libghostty-vt remains the best *reference implementation and test corpus* for sequence parsing, screen state, Unicode, wrapping and key encoding, but is **not** to be linked into delta: it owns the grid (we need a bounded derived view for agents plus reveal overlays), its input encoding happens inside the library while our key-ownership arbitration ("chord vs byte to child, decided by who currently owns the pane") must run before it, it is Zig with its own allocator/threading against our single-threaded `ControlFlow::Wait`, and full libghostty also owns fonts/renderer so it would fight another layout engine over the glyph atlas. So: reimplement against their tests, and say plainly that the "free" parts are fewer than they first looked. Font layer: stable ground is swash + read-fonts/skrifa; cosmic-text has a long-open inability to set font features/variations; parley/fontique is cleaner but still reorganising with no frozen API; DirectWrite is the maximally stable Windows-only option — undecided, revisit after the terminal layer runs.

**Panes, tabs, splits — the model has converged, so this is a "learn it" area, not a gamble** (the user has no confidence here and asked to borrow where possible). A binary tree whose leaves hold terminals and whose internal nodes are horizontal/vertical splits is what tmux, i3/sway, Konsole, wezterm and Zed all landed on; the outliers are kitty's OpenBSD-style tag windows and Windows Terminal's shallow single split, the one people complain about. **Axis-by-axis copy targets** (researched 2026-11-07; the user refuses to invent these — "我们定不好，找个最好的学一学"):
1. *New split pays from whom* → behaviour from **i3** ("every window gets an equal amount of space", only the split pane pays), interface from **wezterm** (`SplitPane{ size = Cells | Percent }`, default Percent=50) because an agent splitting a pane must be able to request an exact size; ghostty has no size parameter at all.
2. *Whole-window resize* → **i3** proportional re-layout. Verified bad elsewhere: wezterm does not preserve ratios (issue #2865, discussion #6705 closed as duplicate — "only one pane grows while others remain static"); tmux's `window-size latest|latest-large|manual` causes the classic "smaller client shrinks everything"; ghostty needing `equalize_splits` proves it doesn't re-layout.
3. *Minimum pane size* → **nobody has solved this** (verified negative: no documented floor in wezterm/ghostty/kitty/Konsole references; ghostty's `resize_split` steps in pixels, sub-cell). Ours to design, keeping the one consensus rule: **refuse the shrink rather than collapse or hide a pane** (tmux and i3 agree).
4. *Pane closes* → space to the surviving sibling exactly once via **i3's redundant-parent collapse**; focus back to the **previously focused pane, deliberately opposite tmux** (focus-by-order is the most-cited papercut); zoom restore from **ghostty** (`split-preserve-zoom:navigation`, plus the 1.4 stale-zoom-indicator fix).
5. *Divider drag / resize keys* → dragging moves **one internal edge, adjacent panes only** (i3 "grab the border and move it"); key set = **Konsole's four** (Expand / Shrink / Equal size to all views / Toggle maximize); zoom semantics = **wezterm** ("zoomed pane takes all space; switching off restores the prior split arrangement"). Make this axis a regression suite: ghostty broke divider dragging in 1.3 (#11412) and mis-transfers focus on border clicks (#11405).

**The layout system is ONE coherent set: herdr + tmux** (user's pick; they first typed "helix" then corrected to herdr, 2026-11-07, and they reject per-axis assembly — "我要用一套，而不是拼装"). Verified against `herdr.exe pane --help`: the split of work is lopsided and that is fine. herdr already supplies the object model, the agent semantics and the persistent-session server (headless `herdr server`, `session attach`, `--remote`, worktrees, tabs, its own socket API), so **tmux's remaining contribution is arrangement policy only** — named layouts (`main-vertical|main-horizontal|tiled|even-horizontal`) and the main-region concept (`main-pane-width/height`) — because herdr's `pane split` offers just `--direction right|down --ratio <FLOAT>` with no layout algorithm. Under the unifying law **"topology is persistent data, sizes are derived"**, a tmux layout must be expressed as the set of ratios it produces, never as cell arithmetic; that is what keeps the two from fighting.

**Delta's position resolved: ACP host + MCP server, never an agent author (2026-11-08, the user's own objection and then their own fix).** The user first raised the dilemma sharply — herdr manages *other people's* agents (claude/qoder/deepseek/hermes CLIs) whose skills, MCP and model loops are far better than anything we would write, yet everything delta promises (git-like ledger, sandbox, backup, AI window rendering, AI communication) seems to require being in the loop, and "我们自己写个又太垃圾了". The resolution, which the user then extended themselves:
- **The deciding variable is who is in the write path, not who does the thinking.** Verified evidence that herdr deliberately is *not*: its skill manual's only file touch is a fallback — *"ask the agent to write it as Markdown in a temporary directory and reply only with the file path, then read that file on the same machine"* — and `agent start` merely launches a CLI in a pane. That is exactly why herdr has no real diff, no progressive reveal, and must infer state from the screen plus `report-agent`. Delta's promise is a step *beyond* herdr for this reason, not a copy of it.
- **ACP supplies the standard entry point** (see [reference-acp](../references/acp.md)): `fs/write_text_file` and `terminal/*` are **client-implemented**, so the host performs the write and runs the command → the ledger rows, path jail, backup-before-delete, approval and reveal overlay all attach there. `session/request_permission` + `elicitation/create` are the wire formats for ask-not-command; `session/load` is the listed resumable actor/session row; `session/update`'s plan/tool_call/message-vs-thought chunks are the overlay's event source. So the "AI 沟通" layer is largely protocol-existing, not to-be-invented — the user's own suspicion was correct on three of their items.
- **Load-bearing law the user must keep:** ACP notifications are lossy when detached, so **persistent facts may only be recorded at the points we enforce (fs/write_text_file, terminal/create); the update stream may only be used for display.** Otherwise the structured database has holes precisely while nobody is watching.
- **What stays entirely ours** (verified absent from ACP): persistent per-path read/write ACL, roles, approval *policy*, and the multi-agent roster — hence "one workspace = one group chat, members = N ACP sessions (N child processes)" is our object model. Corollary the user liked: **many agents ≠ many vendors**; N opencode sessions with different roles/models/permissions gives a multi-agent group with zero compatibility layers.
- **Hard physical constraint on permissions:** writes can genuinely be refused (they pass through us), but **reads cannot be refused at the ACP layer** — an agent is an ordinary process and may read with its own tools. True read-deny needs OS identity: separate account / integrity level + NTFS ACL, or a pruned/copied worktree. The UI must therefore mark read/write guarantees at *different strengths*, or we sell an undeliverable promise. Shell side-channel (`sed`, redirection, via `terminal/*`) keeps the FS-diff + jail + backup net mandatory: ACP improves attribution, it does not replace enforcement.
- **New conflict found: two permission engines — DECIDED, and by a third option I had not listed.** opencode ships its own allow/ask/deny with glob patterns and **last-match-wins**, several auto-approve paths ([docs](https://opencode.ai/docs/permissions/)), and nested subagent edit permissions are still open (issue #13872). The user resolved it with *"5的话我们自己权限。不再使用opencode权限，opencode权限好的部分我们抄过来就行"*: **their engine is not used at all** — neither "set them permissive and treat theirs as noise" nor "compile our policy into their config". delta's engine is the only one in the chain, so no double prompt exists by construction; what survives is copying the good parts of their semantics (the six dimensions in [reference-opencode](../references/opencode.md)). Remaining exposure that this decision does NOT remove: the guarantee holds only if **every write the agent makes is actually routed through our client methods**, and ACP does not give us that. Verified spec wording (agentclientprotocol.com/protocol/file-system and /terminals): the client advertises `fs.readTextFile`, `fs.writeTextFile` and `terminal` in `initialize`, and *"If `readTextFile` or `writeTextFile` is `false` or not present, the Agent MUST NOT attempt to call the corresponding filesystem method"*, same shape for terminal. **That is a prohibition on calling us when we are absent — advertising the capability creates no obligation to use it.** So a capable client can still be bypassed by an agent that edits through its own tools, and the ledger, path jail and backup-before-delete would never see it. The real requirement is therefore: advertise all three, **and verify in practice that opencode routes its edit/write through `fs/write_text_file` and its command execution through `terminal/*`** — plus know what to do about anything that does not (the two levers are an OS-level path jail / separate account, which is the same lever read-deny needs, or refusing to host agents that bypass us).
- **"AI 管理 AI 的权限" (user: 听起来很危险，但这是未来)** touches the frozen law *agents may never self-grant leases or change their own approval thresholds*. Attenuation-only delegation (grant ⊆ what the grantor holds; macaroon/capability semantics) is the mechanism that keeps it survivable, plus grant rows carrying a delegator chain, an expiry (herdr's `--source/--seq/--ttl-ms` fenced authority is the precedent), and a human root ceiling no agent can widen and that is always visible.
- **opencode as the primary bet — accepted direction, still to be validated by integration.** Rationale: open source (auditable, and their tests are carryable per 记忆条目 project-kite-strategy，本目录未收录，规则见 ../AGENTS.md), multi-provider LLM (so model switching stays the agent's business via `session/set_mode`; we only attribute and display), **native** ACP rather than an adapter shim, ready subagent/role machinery. ACP coverage is broader than feared (Gemini CLI, OpenCode, Qwen Code, Kimi CLI, Hermes Agent native; Codex via official adapter; Claude Code via Zed's SDK adapter; DeepSeek/GLM/Groq via acp-llm-adapter), so the bet is a quality choice, not a necessity — and it must not be written into the design as "only one agent exists", because Tier C fallbacks stay part of the product.
- **Unified live view is the easy direction, and this was the user's fear inverted:** an ACP-speaking agent has *no* TUI (stdio JSON-RPC child process) — nothing to scrape, no ANSI, no IME/repaint cost; rendering is a projection of `session/update`. The hard case is the opposite (TUI-only CLIs = herdr's screen-scraping problem). Known gap: ACP cannot carry a vendor CLI's own palette/subagent tree/cost counters — see zed #59566 — so copy Zed's **raw ACP traffic inspector** (`dev: open acp`) as the standard escape hatch, with "run the native CLI in a terminal pane" as the documented tier downgrade rather than a design failure.

**Two decisions taken 2026-11-08, plus the @ mechanism.**
- **Permissions: delta writes its own engine** (the user chose this over compiling policy into the agent's config), **but must absorb opencode's dimensions** — the six worth copying and the one explicitly not copied are recorded in [reference-opencode](../references/opencode.md). The consequential ones for our design: the path jail becomes a **pre-stage of rule evaluation** (opencode checks `external_directory` *before* read/edit rules), sensitive **reads become `ask`** because read-deny is unenforceable at the ACP layer, and persistent grants store **patterns** so a grant row is `(actor, action, pattern, delegator, ttl, granted_by_human)`.
- **Group chat runs on @ mentions**, for human→AI and AI→AI, and the user named the failure mode themselves: *"防止 agent 互相乐此不疲提问，反复说话，token 爆炸"*. Three structural advantages make it tractable here and nowhere else: (1) **delta is the only postman** — ACP has no roster and no agent↔agent semantics, `session/prompt` is one client-issued turn, so every @ crosses our transport and rate-limiting/refusal is protocol-reachable (herdr, screen-level, cannot do this); (2) **an @ must be a typed ledger object, not text** — sender, recipients, owning task, parent question, effect (advisory|authoritative), hop budget, TTL, accumulated cost — no control is implementable over plain-text mentions; (3) **default must be advisory** — otherwise chat is a command channel in disguise and a low-trust agent drives a high-trust one by asking, which is the same privilege-escalation class as agent-manages-agent permissions. `@` is our own extension semantics; the industry's peer track is A2A, and other ACP clients will not interoperate on it.
- **Anti-runaway controls, ranked by force** (each traceable): hard **hop limit / question TTL** (the standard first defence, per [neuraltrust](https://neuraltrust.ai/blog/a2a-loop)); **a reply must be a state transition, not talk** — either close the question object or change a task row, otherwise the turn is rejected outright (strongest control, since idling becomes structurally unproducible); **no redistribution back to the message you just received** ([explicit rule](https://dev.to/alessandro_pignati/stop-the-loop-how-to-prevent-infinite-conversations-in-your-ai-agents-ekj)) → an agent may not re-question its last sender unless its own task row changed state, which kills two-hop ping-pong; **no self-wake** — answering A's question must not start a fresh A turn unless A has an open task awaiting it, deliver only to idle + addressed + with a pending question; **cost metered per thread with human-gated thresholds** (quantified: *a 10-turn loop sends roughly 50× the tokens of a single linear call* — [falconer](https://falconer.com/guides/agent-loops-token-budget/)) and never self-raised, which reuses the frozen "agents may not change their own approval thresholds"; **idempotent dedup** of identical unresolved (sender, recipient, normalised question); and **throttling must be visible** — hitting a cap writes a "throttled" row showing who/which task/what cost, rather than dying silently, which is the same law as "exists-but-invisible must be counted" in the chrome layer. **After the decision rules below, only the last two of these seven still apply** (per-thread cost accounting and visible throttling): one-speech-per-ballot plus human-only vote initiation plus no re-vote makes every ballot provably finite, so hop budgets and anti-ping-pong rules became dead weight — kept here as provenance of why they were dropped. Reference taxonomy to read: [Uncovering Infinite Agentic Loops in LLM Agents](https://arxiv.org/html/2607.01641v1).

Still unresolved: **whether one sidebar rail carries both the file tree and the agent list or there are two rails**, and which row shows agent lifecycle status; **whether the per-question editor sourcing above is accepted** (helix kernel / Fresh agent semantics / vis structural-regex addressing / nvim+Emacs headless contract / Zed presentation / vis+lite-xl as size rulers) — the split into per-question teachers is mine, and the user has not chosen it; note this is a deliberate exception to the "one coherent set, not an assembly" rule, justified only because the questions really are separate layers (kernel shape vs agent protocol vs addressing vs presentation vs yardstick), and no single product wins all of them; **whether an agent should name text structurally (sam-style) or by byte range in a Transaction**, which decides how the ledger's edit rows are written; which action classes need approval rather than auto-approve, whether an instruction whose context reference is stale or missing gets refused or restated-and-confirmed, **what to borrow from each tool in the source pool** (outside the layout system), ~~whether the server-process-owns-ConPTY shape is adopted~~ → **settled by the window laws, not by a choice: a close that must not kill and must be refusable can only hold if the PTY belongs to the session object** (two shipping precedents agree, **herdr's headless `server`** and **Fresh's per-directory daemon**, the latter having already hit and fixed the failure modes — detached daemon killing running agents, `--wait` blocking on an invisible editor, socket names too long for deep paths, half-open client stalling the daemon), our own layout-algorithm vocabulary on top of herdr's ratios (which named layouts, and what main-region ratio), the minimum-pane-size contract (no upstream has solved it), whether `done` should be self-reportable at all, and where the IME composition string gets drawn — grid cell or floating overlay (herdr's ASCII-input-source trick covers prefix keys, not the composition display). The last one remains the top technical risk: it is what broke kite, it is orthogonal to ADE and to shells, and it is the hardest half of "works with every shell".

**Group decision mechanism — the user's design, decided 2026-11-08 (not borrowed; parliamentary procedure is the closest mature analogue and is now in the reference pool).** Rules as stated: (1) **human abstention ⇒ the AI majority decides**; (2) **no re-vote** (the earlier "debate then re-vote as final adjudication" is dropped); (3) human choosing 再议 ⇒ everything stops until the human asks again; (4) **only the human may initiate a vote**; (5) an AI's question is answered by the human picking an option, and the human decides whether that option set is produced by group deliberation; (6) **one speech per actor per ballot, then vote**; (7) **tie ⇒ human decides**; (8) **an actor may vote on its own ballot** — the user's stated reason: *"这无所谓。因为这是群体，不是只有一个人"*. (Reading to confirm: 再议 exists only among the human's options; AI has neither 再议 nor 弃权.)
- Structural wins from these choices: **agenda control sits with the human** (items 4-5), which resolves the "whoever authors the options holds the real power" problem; **every ballot is provably finite** (one speech + one vote + no re-vote → N+1 turns, no loop), so most of the seven anti-runaway controls are now unnecessary — only per-thread cost accounting and visible throttling still matter; and 再议 is a halt-and-wait, not a loop generator. Cost of item 7: a tie no longer preserves the status quo (as it would under Robert's Rules), so **engineering a tie becomes a blocking tactic** — recorded as an event is enough, no new mechanism needed.
- **Unresolved conflict A (statistics vs the user's justification):** item 1 makes AI votes an authority source, and the measured fact is that *roughly three-quarters of a panel's nominal independence is lost to correlated errors* ([Apple ML](https://machinelearning.apple.com/research/correlated-llm-evaluation-panels)); with N opencode sessions on the same model/config the effective voter count may be ≈1. The user's argument is *structural* (a group, not one actor), the counter-evidence is *statistical* — both stand, they don't support each other. Cheapest guard that keeps their rule: on abstention, **display the decision as "5 votes, effective independent opinions ≈1.3"** so the human sees what they delegated to. (Alternative they may or may not take: below an effective-independence threshold, abstain degrades into item 7 → human.)
- **Conflict B (collision with a frozen law) — RESOLVED by Qoder on the user's explicit delegation (*"哪个好选哪个，你替我选"*), so: decided, and the user owns the veto.** Item 8 (self-voting) contradicts *"agents may never self-grant leases or change their own approval thresholds"*. The widest hole is not ordinary decisions but **ballots whose subject is an actor's permission set** (two agents voting for each other's write access = a 2:0 self-grant in ballot clothing). **Chosen fix — recusal rejected in favour of a ledger invariant:** every row that changes an actor's authority (permission grant/revoke, lease grant/revoke, approval-threshold change, capability-tier change) accepts only `human` as its author kind, and a ballot outcome may never be such a row's `authorized_by`. Recusal was rejected because it is per-voter: it catches the mutual-grant pair but **misses three agents granting a fourth** — nobody in that tally is a beneficiary, yet it is still a self-grant by proxy.
- **How the law changes:** it is *not* amended, it is **strengthened** — the prohibition stops depending on agent discipline and holds by construction. Rule 8 stays fully intact for every other subject, so the user's justification (*"这无所谓。因为这是群体，不是只有一个人"*) is honoured where it was meant to apply. AI may still propose, second and argue authority changes; the human's hand writes the grant, and the work for the "AI 管理 AI 的权限" future is making that click cheap (batch grants, time-boxed windows, expiry in herdr's `--source/--seq/--ttl-ms` shape), not making ballots able to authorize.
- **The cost, recorded so it can be reversed:** rule 1's **人类弃权 ⇒ AI 决定 is narrowed to non-authority questions** — on an authority question, abstention means nothing changes. If the user wants rule 1 unconditional, this whole resolution must go back to narrow recusal.
- **Two kinds of write lease, `held` and `parked`** (this is how the ambiguous *"写lease，是两种"* was read — the phrase followed the words 写lease directly): a task blocked on a 再议 ballot keeps its pane and identity, drops to read + speak only, and must display who waits and for how long. This closes the parked-ballot open item, which had been load-bearing because the worst shape was an agent halted on a human decision that still held write authority — and it satisfies *"关掉，不然你都不知道他还跑着"* without killing the process. herdr's comparable state is *inferred* from an approval dialog on screen ([reference-herdr](../references/herdr.md)); ours is exact because we are the one that parked it.
- **Approval granularity — the standard chosen for the user** (his phrase *"审批粒度的话是按照标准"* did not name it): approvals bind to the triple **`actor × action class × resource glob → allow|ask|deny`**, never to a single action instance. Action class uses ACP's `tool_call.kind` vocabulary; glob matching and **last-match-wins** are copied from opencode ([reference-opencode](../references/opencode.md)), its permissive `external_directory` default still is not. An approval may carry the agent's proposed patterns so the human saves them once.
- **Unresolved item C (where persuasion happens once re-voting is gone):** items 2+6 leave the single speech as the only influence channel, so an implementation fork must be chosen: votes collected **after** all speeches (herding moves from vote-order to speech-order — see the stance-convergence finding that answer changes and convergence alone cannot distinguish updating from conforming) vs **at** speech time (early speakers can't hear later arguments, so no real debate). A cheap device compatible with "no re-vote": a **blind pre-vote recorded as evidence only, never as the decision**, which finally gives *consensus ≠ truth* a measurable foothold (it lets us tell "changed because of that argument" from "changed because everyone else picked A"). Whether to pre-vote reuses item 5's deliberation switch.
- **Unresolved item D (forced preference):** AI cannot abstain, only A..D, so a model with no opinion still casts a vote — known forced-choice bias, which further depresses the effective independence from conflict A. A distinct "无意见" option would need semantics different from human 弃权 (not counted in the numerator, and it must NOT transfer authority, or it collides with item 1).
