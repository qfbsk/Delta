## 2. 输入层（源码读于 2026-11-08）

- **WezTerm 20240203**（MIT，Rust）是可转写的 Windows 输入链：
  - `window/src/os/windows/window.rs` 的 `key()`：WM_KEY* → RawKeyEvent/KeyEvent。
  - `termwiz/src/input.rs` 的 `KeyCode::encode()`：legacy xterm + CSI-u。
  - `wezterm-input-types` 的 `encode_win32_input_mode()` / `encode_kitty()`。
  - `wezterm-gui/src/termwindow/keyevent.rs` 的 `process_key()`。
  - Imm32 IME，自带 preedit；ConPTY 走 kernel32（`pty/src/win/psuedocon.rs`），可选 `conpty.dll`。
  - 缺：UTF-16 代理对、Alt-Numpad、VK_PACKET/自动重复。
- **Windows Terminal 1.26**（MIT，C++/XAML）是行为基线，不是转写对象：
  - `src/terminal/input/terminalInput.cpp` 的 `HandleKey()` 覆盖上面那些缺口。
  - win32-input-mode 9001 的格式是 `CSI Vk;Sc;Uc;Kd;Cs;Rc_`。
  - 支持 kitty 协议；没有 `WM_IME`（IME 是 TSF，在 `TermControl.cpp`）；它是 ConPTY 的维护者（`src/winconpty`）。
- **tmux 3.8**（ISC，C）只取窗口/pane 模型和 `tty-keys.c` 的序列匹配；它的 prefix 键模型**不是** Delta 的。
- **fish 4.9.3**（GPL-2.0）：`src/input/{decode,input,binding}.rs`、`src/key.rs`、`src/reader/reader.rs` 是 odd 的行编辑/ESC 时序参考；POSIX 宿主。
- **kitty 0.50**（GPL-3.0）：`kitty/key_encoding.c`、`keys.c`、`vt-parser.c` 是键盘协议和纯字节编码参考；无 Windows。
- **Ghostty 1.4.0**（MIT，Zig）：`src/input/{key,key_encode,Binding}.zig` 只给键模型/绑定/编码；**没有 Win32 apprt**，不能当 Windows 输入参考。

## 3. 终端图片协议（源码读于 2026-11-08）

- **WezTerm**：同时支持 kitty graphics、iTerm2 OSC 1337 `File=`、sixel；图片是 cell 属性，走 glyph/atlas 缓存；kitty 删除只实现 `d=a/A` 和 `d=i/I`，其余告警。
- **kitty 0.50**：kitty graphics 的参考实现。动作 `t/T/p/d/q/f/a/c`；介质 direct/base64/file/temp/shm；placement ID、z-index 桶、滚动/删除、动画帧；存储上限 320 MB、单边 10 000、加载 400 MB。
- **Ghostty 1.4.0**：只实现 kitty graphics，没有 sixel 解析器；每屏 `ImageStorage`、placement、z 层 `below_bg`/`below_text`/`above_text`、跟随滚动的 pin、动画；Windows 上 `t=s` 共享内存是 `UnsupportedMedium`；`windows.zig` 会校验 UNC/设备名/保留名。
- **Windows Terminal**：只实现 sixel；图片是按行的 `ImageSlice`，没有 image ID / z-index / 删除 / 查询；D3D atlas 绘制（D2D 后端不能画，GDI 用 `StretchDIBits`）；剪贴板只接受文本，没有 CF_DIB/CF_PNG。
- 可借的形状：kitty graphics 为主、sixel 兼容；存储/placement/删除/动画看 kitty + ghostty；Windows 渲染看 WT atlas 或 WezTerm glyph cache。图片必须跟着 cell 进 scrollback，并且经得起擦除/滚动/重排。

## 4. ConPTY 与图片（2026-11-09 实测）

- 系统 kernel32 ConPTY **会丢掉子进程输出里的 APC/DCS/OSC**：一个原生 Rust 探针写 `ESC _ G`、sixel DCS、OSC 标题，终端 reader 只收到普通 SGR/文本，没有对应字节。
- 换成 WezTerm 20240203 自带的 `conpty.dll` + `OpenConsole.exe`（从它的 Windows release 里取出）后，APC `a=q` 查询能穿过去，但真正的 kitty PNG APC 到达时变成了 `?` 文本，图片没有放上去。不可用，改回 kernel32。
- 应用自己发的图片仍然被挡；**文件图片显示可用**（当时的实现有 `--image <png>`，已随代码删除）。

## 5. opencode 2.2.6

安装与源码：

- 程序在 `D:\OPENCODE\opencode.exe`，v2.2.6；源码钉在 `E:\Delta\vendor\opencode-2.2.6`。

ACP：

- `opencode acp`（可带 `--login`）在 stdio 上说 NDJSON，一行一个 JSON-RPC；它每个进程起一个**私有** server（`Standalone.start()` → `serve --stdio --port 0`），随机密码、不持久化 endpoint，TUI 接不上去。
- 想和 opencode 的 TUI 共享活会话：跑一个共享的 `opencode serve`（已知 `OPENCODE_PASSWORD`），在 AI 窗口里 `opencode --server <url> --session <id>`，even 走这个 server 的 HTTP/SSE。
- 协议：`protocolVersion: 1`；`promptCapabilities {image:true, embeddedContext:true}`；session 方法 load/list/delete/resume/close/fork/additionalDirectories；`session/request_permission` 的选项是 once/always/reject；**没有** ACP `fs/*` 或 `terminal/*`；没有 SSE MCP；audio/video 丢掉。
- `always` 会在 opencode 里写一条保存的 allow；按 Delta“只有人能授权”的规矩，`allow_always` 必须由人选。

HTTP（共享 server）：

- `POST /api/session` 建会话；`POST /api/session/:id/prompt` 发提示；`GET /api/session/:id/message` 读消息；`GET /api/event` 是 SSE，易失、不重放；`GET /api/experimental/session/:id/log?after&follow` 是持久日志；`POST /api/session/:id/interrupt` 中断；`POST /api/session/:id/permission/:req/reply` 回权限。
- 实测：`POST /api/session` 带 `{"location":{"directory":"E:/Delta"}}` 返回 `data.id`；空的 body 用 server 的 cwd。`POST /api/session/:id/prompt` 带 `{"text":"...","delivery":"steer"}` 返回被接纳的 user 消息。`GET /api/session/:id/message?limit=10&order=desc` 当时只返回 user 消息；`GET /api/event` 只返回 `server.connected`，实验持久日志只有 `log.synced`。
- 共享 server 要 HTTP Basic auth：用户名 `opencode`，密码就是 `OPENCODE_PASSWORD`；不带是 401。

事件与工具：

- 工具事件：`session.tool.input/called/progress/success/failed`；权限 `permission.asked/replied`；空闲 `session.status`。
- MCP 工具默认 Code Mode（`codemode:true`），所有工具合成一个 `execute`；设 `codemode:false` 才能看到单个工具。
- 写路径：把 Delta 的 MCP server 注册成 `mcp.servers.delta`；禁掉内置 `edit`（隐藏 write/edit/patch）和 `shell`，保留 `read/glob/grep`。MCP 工具的资源是 `*`，所以路径/命令规则必须 Delta 自己执行。
- 结论的识别：assistant 的 `text` / `reasoning` / `tool` 是分开的；reasoning 和 tool 组折叠；**没有 `final` 标志**，`idle` 之前的最后一段 `text` 就是结论。群聊读 `text` + `idle`，过程去 AI 页面。

图片：

- opencode 的 `prompt.paste` 就是 `Ctrl+V`；剪贴板读 `image/png` + `text/plain`；Windows 空粘贴有 WT < 1.25 的回退；图片变成 data-URL 附件，预览最多 3 个；本地 20 MiB，core 缩到 2000×2000 / 5 MiB base64。
- ACP 的 `image` block 要 `data`（base64）或 `uri`（file://）；`embeddedContext` 也能塞资源。单附件 20 MiB；模型图片预算 25 MiB，超了从最旧的开始丢到 ≤15 MiB；只收 png/jpeg/gif/webp（PDF 会变成 media part）；其他 mime 丢弃。ACP 层除了 JSON-RPC 消息上限没有别的尺寸检查。

provider（登录）：

- `GET /api/integration` 列出集成、认证方式和已有连接；`POST /api/integration/:id/connect/key` 带 `{"key": "..."}` 存一个 key（204）。两个都要 server 的 Basic auth。
- 用户给的 key 是 **DeepSeek 平台**的，不是 OpenCode Console 的：`deepseek` 集成接受它；`opencode` 集成拿它返回 401 `provider.auth`。
- 模型 id：`deepseek/deepseek-flash`（V4.1 Flash）、`deepseek/deepseek-v4-pro`；`opencode/deepseek-v4.1-flash-free` 要 OpenCode Console 登录。
- 建会话可以带 `model: {providerID, id}`；当时 `delta-even` 每个会话都用 `deepseek/deepseek-flash`，出错时打印 `message.error.message`，不再挂着。
- 共享 server 的接法：Delta 在第一个 even/opencode 标签时起一个隐藏的 `opencode serve`（随机端口 + 密码），通过 ConPTY 传 `DELTA_OPENCODE_SERVER` / `DELTA_OPENCODE_PASSWORD` / `OPENCODE_PASSWORD`，even 连它，`opencode --server <url>` 也连它。GUI 里验证过：opencode 标签能列出 even 刚建的会话。
- `opencode --server <url> --session <id>` 能把 TUI 接到共享 server 上的活会话（在 Delta 里验证过：会话、模型、tokens、cost 都能看到）。even 通过 `%TEMP%\delta-even-<pid>.open`（成员 + 会话）和 `.close` 请求开关页面；Delta 轮询这些文件，even 标签退出时关掉所有成员页面。
- `POST /api/session/:id/interrupt` 返回 `{interrupted:true}`，会话以 `outcome:"interrupted"` 结束；even pane 关闭时 Delta 读 `%TEMP%\delta-even-<pid>.session`（even 写的），向共享 server 发中断；正常关窗口会杀掉整个 server。
- **没有验证到一条真实的 assistant 回复**。TUI 一度显示 “Connect provider”；后来 DeepSeek key 通过 HTTP 接上了，但“模型真的回话”这一步没有留下成功记录。见 [04](04-未定.md)。

权限语义（官方文档 https://opencode.ai/docs/permissions/ ，2026-11-08 读）：

- “Agent rules are appended after global rules; they do not replace the global array.”——规则是追加，不是覆盖。
- “A policy can hard-deny a permission check… It turns `allow` or `ask` into `deny` and never grants access.”——硬拒绝只能收紧。
- “`external_directory` … is checked against `external_directory` before its `read` or `edit` rules.”——外部目录检查是规则求值的前置阶段。
- “Every agent starts with this ordered base policy: `{ "action": "read", "resource": "*.env", "effect": "ask" }`”——`.env` 这类敏感读默认问。
- “Allow always … Approve it and save the tool's proposed patterns for the project”——持久授权存的是 **pattern**，不是路径。
- 受控动作是 `edit` / `shell` / `webfetch`（读通过基础策略），结果是 `allow|ask|deny`；匹配是 **glob，最后一个匹配生效**；粒度有 *Ask once* / *Allow always*。
- **不能抄的一条**：“The default policy allows `external_directory`, so external paths are not prompted unless you add a rule.”——它默认放行外部目录，和 Delta “误杀优于静默”的偏向相反（见 [文档 06](../06-我们跟谁学.md)）。

## 6. tmux 3.8

- 默认键表（prefix 之后）：`0-9` 选窗口、`l` 上一个窗口、`n`/`p` 下一个/上一个、`w` choose-tree；`o` 下一个 pane、`C-o`/`M-o` 旋转、`q` 显示编号、`z` zoom、`!` 把 pane 拆成独立窗口、`%` 竖分、`"` 横分、`C-方向键` 调大小；`[` 进 copy-mode，`q` 或 `Escape` 退出。
- tmux **只保留 prefix**；不跟 prefix 的键原样交给 pane 里的程序。
- prefix 是键表切换（`server-client.c:1545-1551`）：任何时候按到 `prefix`/`prefix2` 就切到 prefix 表并吃掉这个键；匹配到的绑定执行后回 root 表，除非是 `bind -r` 可重复（`repeat-time` 默认 500 ms，`initial-repeat-time` 0）。
- **`prefix-timeout` 默认 0 = 关闭**（`options-table.c:514-522`），按完 prefix 会无限等下一个键。
- 默认 `prefix+c` 新窗口、`prefix+x` 杀 pane（带确认）、`prefix+z` zoom。**`x` 杀的是 pane，不是窗口。**
- `escape-time`：3.8 源码是 10 ms；早期 man page 被引成 500 ms。引用前重新核对。
- `break-pane -W` 把 pane “从平铺布局里提出来”变成浮动；`move-pane` 接受 **z-index**，“zero is the front”。
- 后台窗口还在跑；非当前窗口的输出不显示，`monitor-activity` 只做提示。
- 进程退出默认**会销毁 pane**（“When the shell command completes, the window closes.”）；要保留得开 `remain-on-exit`，`respawn-pane` 负责复活。
- 明确**没有**验证、引用前要重读手册的：`alternate-screen`、`allow-passthrough`、`pane-exit-action`、mouse-capture 绕过键、`exit-enter` 家族。其中 `pane-exit-action` 最值得先查，它可能是“pane 退出后怎么处置”的先例。

## 7. Ghostty 1.4.0

官方 [Option Reference](https://ghostty.org/docs/config/reference) 和源码，2026-11-08：

- `unfocused-split-opacity`：不聚焦的分屏“淡一点”，不是隐藏。
- `background-opacity`：1 完全不透明，0 完全透明。
- `minimum-contrast`：前景/背景最小对比度，1–21。半透明要有对比度兜底。
- `window-decoration`：只是“偏好”，承认操作系统可能覆盖。
- `resize-overlay`：改尺寸时用临时浮层显示尺寸，不常驻占位。
- `src/apprt/` 只有 gtk/embedded/none，macOS 是 Swift；**1.4.0 没有 Win32 apprt**。libghostty 能编 Windows/WASM，但没有 WM_KEYDOWN/ToUnicode/IME/ConPTY 宿主。
- 键模型：`KeyEvent{action,key,mods,consumed_mods,composing,utf8,unshifted_codepoint}`；`Mods` 是打包的 u16，带左右和 lock；`Binding.Set.getEvent` 依次探物理键、unicode、unshifted、catch-all；`key_encode.encode` 有 kitty 标志就用 kitty，否则 legacy（C0 表 + fixterms CSI-u + xterm modifyOtherKeys）。
- 1.2.0 发布说明提到顶部“简单的进度条”，以后由 tab 承载进度；1.3.0 提到“minimal overlay-style scrollbar”，不占网格列。这两条是发布说明的印象，没有深入验证。

## 8. herdr 0.9.5

装在 `D:\herdr`；运行状态在 `C:\Users\QFBSK\AppData\Roaming\herdr`（`herdr.sock`、`session.json`、日志、`session-snapshots/`）。以下来自 `--default-config`（380 行，2026-11-08 通读）和 `--skill`、`pane --help`：

- 键模型：`[keys]` 有 `prefix`（默认 `ctrl+b`），两种写法：`"prefix+n"` 要 prefix，`"ctrl+alt+n"` 是终端模式下的直接组合键。它自己的可靠性建议：最可靠的是 `ctrl+字母`、功能键、显式修饰的 chord。**这套 prefix 模型没有被 Delta 采用**；用户定了 Windows 直接组合键。
- `copy_on_select = true` 默认；设 false 时选择保留到 Ctrl+C。`remote_image_paste = "ctrl+v"` 只给 `herdr --remote`。
- `cursor = "auto|native|drawn"`：auto 在原生 Windows 和 WSL 上画自己的光标，避免 ConPTY 闪烁。
- prefix 模式可临时把输入法切成 ASCII（Windows 上是切 IME），best-effort。
- `pane_scrollbars = false` 可以收回滚动条那一列。
- `mouse_capture = true` 抓鼠标给自己的 UI，但 pane 里的程序请求鼠标时仍能拿到（lazygit、btop）。
- `[[keys.command]]` 有三种类型：`shell`（分离后台）、`pane`（临时 pane，命令结束就关）、`popup`（不改 tab 布局的模态终端，宽高可用 cell 或百分比）。
- `[server] headless_cols = 120`、`headless_rows = 40`；接上客户端后用客户端自己的尺寸。
- `scrollback_limit_bytes = 10000000`，注释说对齐 Ghostty 默认行为。
- 状态显示：`status_indicators = "dots" | "symbols"`，symbols 是 blocked/working/done/idle/unknown 各自的静态字形。`report-agent --state` 只收 `idle|working|blocked|unknown`，但检测词表里有 `done`——**自报状态和观察状态是分开的**。
- 侧栏是 token 语言：`[ui.sidebar.agents].rows` 是“行的列表”，内置 token 有 `state_icon, state_text, machine, workspace, tab, pane, agent, terminal_title, terminal_title_stripped`，`$name` 取 `report-metadata` 上报的值；可按 agent id 用 `rows_by_agent` 整行覆盖。
- `resume_agents_on_restore = true` 重启后把 AI pane 恢复到原生会话；`startup_per_agent_delay_ms` 错开。
- `pane` 子命令：list/current/get/layout/process-info/neighbor/edges/focus/resize/zoom/read/rename/input/split/swap/move/close/send-text/send-keys/wait-output/run/report-agent/report-agent-session/release-agent/report-metadata。`split --direction right|down --ratio <FLOAT>`；`close <pane_id>` 必须给 id；`pane input --right-click herdr|pane`。
- `agent start` 要求已有一个可用的 shell pane，**从不创建/分屏/移动布局**；布局和 agent 生命周期是两层。
- `pane report-agent` 可以带 `[RESUME_ARG...]`，即重启后恢复这个会话的命令。
- 状态判定靠看 pane（idle/working/blocked/done/unknown），`blocked` 表示识别到批准或提问对话框；`agent explain` 说明为什么这样判；投递有三个确认，`agent prompt --wait` 在没开始干活时以 `agent_prompt_stalled` 失败。
- `agent start --kind` 列 21 种 agent，列表由远端 manifest（`manifest_check`）刷新，不写死在 release 里。

## 9. Fresh 0.5.8

`sinelaw/fresh`，Rust，v0.5.8（2026-11-06），Windows 有 msvc zip 和 winget：

- Orchestrator：一个 git worktree 一个 workspace，每个 workspace 有自己的终端和长跑命令；支持 claude/codex/opencode/aider 的可恢复会话；dock 切换；远程/SSH workspace。
- 每目录一个守护进程：`fresh -a` 自动 attach；没有客户端时编辑器继续活着；kitty 键盘协议转发给接上的客户端；socket 名太长用哈希；半开客户端不能卡住守护进程。
- 它的 changelog 本身就是风险清单：“detached daemon 不再一小时没客户端就退出，以前会把跑着的 agent 一起带走”；“`--wait` 对没有客户端的守护进程不再等一个看不见的编辑器”。
- 终端 pane 的 Ctrl+V 坑：“Ctrl+V in a terminal pane reaches the program when the clipboard has no text”，这样 agent CLI 能贴图；可以关掉（`terminal.pass_ctrl_v_without_text`）。
- `fresh --skill` 打印给 agent 用的手册：脚本动词、调用约定、例子；有 Buffers & Editing 组，能**应用文本编辑**，不只是打开文件。
- 有完整 LSP、tab、分屏、内建终端、命令面板、超大文件、沙箱 QuickJS 的 TypeScript 插件。
- 限制：0.x；有插件系统；渲染在字符网格里；README 没提 tree-sitter（官网提了，算未确认）。

## 10. 活体验证方法（2026-11-09 用过并确认）

- 启动 `target\debug\delta-term.exe --shell <batch-or-command>`，stderr 重定向到文件；debug 版会打印 `delta-term: mcp <url>`，轮询它。`--shell` 不是 `cmd`/`powershell`/`pwsh` 时按原始命令行透传。
- MCP endpoint 直接收 JSON-RPC POST，**不需要 `initialize` 握手**就能 `tools/call`。`list_windows`、`read_window` 不用接管（读不限）；`write_window` 需要 AI 持有窗口。
- 找窗口要按**启动的 PID**（`Get-Process ... MainWindowHandle` 或 `GetWindowThreadProcessId`），不要按窗口类名 `FindWindowW`——同类名的旧实例会挡住新实例，探针永远对不上。
- 改尺寸：`SetWindowPos(hwnd, 0, 0, 0, w, h, SWP_NOMOVE|SWP_NOZORDER)`，等约 1.5 s，再读窗口看重排/scrollback。
- ConPTY 怪癖：批处理里的 `timeout /t` 立刻失败（“Input redirection is not supported”），delta 进程随即退出；`ping -n 600 127.0.0.1 >nul` 可以当保活睡眠。
- 只杀自己启动的 PID；已有的 `opencode serve --service` 别动。
