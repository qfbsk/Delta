## A. 用户自己撤回的旧说法

### A1. “一个标签，所有东西都是它的不同 pane”

- 旧说法：“尽量一个标签……所有东西都应该是一个标签的不同 pane。”
- 2026-11-09 用户撤回：现在是有标签有 pane，pane 只属于创建它的标签，程序可以自己开标签。见 [01-已定](01-已定.md) 第 2 节。
- 不许再把它当成“用户想要单标签”。

### A2. “`ctrl+a` 是 prefix”

- 这是我自己读错后写进记忆的；用户从没说过 prefix。
- 2026-11-08 用户定的是 **Windows 键位、直接组合键、无 prefix**。见 [01](01-已定.md) 第 3 节。

### A3. “herdr 的 prefix 键模型已被采用”

- 这是记忆里的一句旧话，已作废。
- herdr 的 `prefix`（默认 `ctrl+b`）只是它的做法；Delta 用的是 Windows 直接组合键。herdr 只作为配置/状态/布局的参考，不是键模型。

### A4. “一个窗口的关闭计数按任务算”

- 我在 2026-11-08 写过“可关闭数按任务算”，用户当场纠正：窗口绑的是 **output / 事件**，不是任务。
- 原话：“我之前不是规定了1个窗口绑定的是output，不是任务。”
- 这条已经进了 [01](01-已定.md) 第 4 节；再写“按任务”就是倒退。

## B. 我提过、被明确否掉的

### B1. 只让 terminal 进分屏，其他窗口各开一个标签

- 实现：`split` 开头有 `if !matches!(self.active_kind(), Some(ActiveKind::Terminal)) { return; }`；solid、even、opencode、文件对话框打开的编辑器、MCP 打开的编辑器、AI 会话页，全部走 `push_tab(pane, true)` 单独开标签。
- 用户判决：“你造了一个只能用于shell的tmux……四不像”；诊断成立，他说“如果是的话，就不用修了”。随后代码全部删除。
- 错在哪：我从旧 `split` 克隆 terminal 命令的形状，推出一条用户没说的限制。tmux 的 pane 能跑任何程序。
- 重写时不许再出现“非 terminal 不能分屏”。

### B2. 2026-11-09 的标签键位表

我提的（用户没有批准）：

- `Ctrl+Shift+T` 新 terminal 标签
- `Ctrl+Shift+G` even 标签
- `Ctrl+Shift+O` opencode 标签
- `Ctrl+Shift+F` 文件标签
- `Ctrl+Shift+D` / `Ctrl+Shift+E` 在当前标签里右分 / 下分
- `Ctrl+Shift+W` 关 pane
- `Ctrl+Shift+Q` 关标签
- `Ctrl+Tab` / `Ctrl+Shift+Tab` 下一个 / 上一个标签
- `Alt+方向键` 在 pane 之间按方向聚焦

用户明确反对的部分：

- **`Ctrl+Shift+Q`**：这个键是我自己加的。
- **`Ctrl+Shift+W` 关 pane**：Windows 的习惯是关标签/窗口，不是关 pane。
- **把 `Ctrl+Tab` 从 pane 循环改成标签切换**，而且没说，结果键盘上再没有 pane 循环。

其余（T/G/O/F、D/E、Alt+方向键）用户没有逐条表态，但整张表都不是他的决定，**不能引用成“用户的键位”**。
重写时这整张表要重新问或重新推，不能直接搬。

### B3. 标签栏的芯片形状

- 我做的：每个标签一个 chip，内容 `"{序号}  {活动 pane 的 label}"`；活动标签换底色 + 底部 accent 下划线；宽度 `(cell_w*22).max(120)`；没有 “+” 按钮，没有关闭按钮；超出右边界直接看不见。
- 这是界面形状，属于用户自己定的范围；我没有先问。用户没有一句认可。
- 重写时最多把它当“当时的实现”，不能当设计。

### B4. 全局拦截 `Ctrl+V`

- 实现：应用层先吃掉 `Ctrl+V`；剪贴板有文字就粘贴文字；只有图片就把它写成临时 PNG，再把 `"{path} "` 写进 terminal。
- 后果：opencode 页面永远收不到 `Ctrl+V`；AI 拿到的是一个路径，不是图片。这和“AI 必须能收到图片”冲突。
- 这是 2026-11-09 审计里我自己的结论，用户没有说“修”，随后代码删除。
- 重写时 `Ctrl+V` 的所有权要按 `insert`/`normal` 和窗口类型重新处理，不能应用层一把抓。

### B5. 我自己写的实现里，被审计出来的缺口

2026-11-09 用户问“你是不是还有别的也是不听指挥”，我按三桶报的。代码已删，但重写时这些都是必须补上的：

**违背已定**

- solid 没有 `Ctrl+A/C/X/Z`，没有 undo；只有 `Ctrl+S`、`Ctrl+Space` 和光标移动。
- solid 没有鼠标选择：点击只放光标，不能拖选、不能双击选词；Windows 传统选择只在 terminal 里有。
- 没有 `normal` / `insert` 状态机，所以“`insert` 里 `Ctrl+C` 给程序、`normal` 里归 Delta”“`normal` 也算 seen”“F1 离开 `insert`”都没有实现；有 terminal 选择时 `Ctrl+C` 永远被 Delta 吃掉。
- `Ctrl+V` 全局拦截（B4）。
- 分屏只收 terminal（B1）。

**我自己定的**

- `Ctrl+Shift+Q`、`Ctrl+Shift+W`、`Ctrl+Tab` 改用途（B2）。
- 标签栏形状（B3）。

**没实现**

- 上面这些之外，权限/记录层按要求留空；浮动 pane、shell 切换 UI、状态行位置、even 的表决界面都没做。
