herdr — "terminal workspace manager for coding agents" — is installed at `D:\herdr` (moved there from `F:\Download\herdr-windows-x86_64 (1)` on 2026-11-07; the empty source dir was then deleted). Version 0.9.5, stable channel, protocol 22, bundling Microsoft Console ConPTY. Not on the PATH.

Runtime state lives in `C:\Users\QFBSK\AppData\Roaming\herdr`: `herdr.sock` / `herdr-client.sock`, `session.json` (persistent session — each workspace stores its `identity_cwd` and per-pane `cwd`, so deleting a saved directory makes herdr open with "Saved directory is unavailable"), plus logs and `session-snapshots/`.

Control it via its socket API: `herdr status`, `herdr workspace list|create|close`, `herdr server stop`, `herdr pane ...`. The user told me to leave herdr and focus back on kite, but raised it again on 2026-11-07 as the layout-system reference for [project-delta](../laws/delta-reasoning.md), so it is active reading material again.

Command groups worth reading when discussing [project-delta](../laws/delta-reasoning.md) (`herdr <group>` with no subcommand prints its full syntax): `api snapshot|schema --json` (self-describing API), `workspace/tab/pane` (topology, split, move, zoom, resize, neighbor/edges), `pane read --source visible|recent|recent-unwrapped|detection [--format ansi]`, `pane wait-output --match/--regex --timeout`, `pane run`, `pane send-text/send-keys`, `pane report-agent|release-agent|report-metadata` (agent self-report guarded by `--source ID`, `--seq`, `--ttl-ms`), `agent list|get|read|prompt|wait|send-keys|start|attach --takeover|explain`, `worktree list|create|open|remove`, `notification show --position --sound none|done|request`, `session`, `machine` (SSH profiles; keys stay owned by OpenSSH), `integration install <agent>`, `config check`, `channel`, `server reload-config`, `update [--handoff]`.

**Key model (from `--default-config`, 2026-11-07) — delta adopts this instead of designing its own.** `[keys]` has a `prefix` (default `ctrl+b`) and two binding syntaxes: `"prefix+n"` requires the prefix, `"ctrl+alt+n"` is a *direct terminal-mode shortcut*. Its own reliability guidance: *"Most reliable direct bindings are ctrl+letter, function keys, and explicit modified chords."* Almost the whole default set is prefix-based (`prefix+c` new tab, `prefix+1..9` switch tab, `prefix+v`/`prefix+minus` split, `prefix+x` close pane, `prefix+h/j/k/l` pane focus, `prefix+e` edit scrollback, `prefix+q` detach, `prefix+r` resize mode, `prefix+w` workspace picker, `prefix+g` goto, optional indexed `prefix+alt+1..9` focus_agent) — indexed ranges are legal syntax. Copy semantics avoid stealing Ctrl+C entirely: **`copy_on_select = true` by default**, and setting it false means selection is retained *"until Ctrl+C"*. `remote_image_paste = "ctrl+v"` exists **only** for `herdr --remote`. Modes have documented precedence: *"These local shortcuts win while navigate mode is open."*

**Windows-specific decisions worth copying:** `cursor = "auto|native|drawn"` where auto *"draws Herdr's own cursor on native Windows builds and WSL to avoid ConPTY cursor flicker, and uses the native terminal cursor elsewhere"*; an opt-in flag that while prefix mode is active it *"temporarily switches the host input source to an ASCII-capable mode so prefix commands register even when an IME is active, then restores the previous input source on exit — on Windows it toggles the IME"* (best-effort, macOS + Windows only); *"On Windows, command strings run through cmd.exe /d /c"*; and a *"Windows only"* option letting ordinary same-account clients control an **elevated** server. Also: `shell_mode = auto|login|non_login` for new interactive panes, `pane_scrollbars = true` (false *"reclaims the scrollbar column and keeps it out of terminal-native selections"*), `mouse_scroll_lines = 3`, `sidebar_collapsed_mode = "compact"`, `window_title = "{hostname}: {workspace}"` with `{pane}`/`{terminal_title}` templating, `[ui.toast.clipboard]`, and resuming agent panes *"into their native conversation sessions"* after restart.

**Verified `pane` surface (2026-11-07, from `herdr.exe pane --help`):** list, current, get, layout, process-info, neighbor, edges, focus, resize, zoom, read, rename, input, split, swap, move, close, send-text, send-keys, wait-output, run, report-agent, report-agent-session, release-agent, report-metadata. Shapes that matter: `split [PANE_ID] --direction right|down --ratio <FLOAT> --cwd --env K=V` (split size is a float proportion an agent can name); `resize --direction left|right|up|down --amount <FLOAT>` (one internal edge, adjacent panes only); `zoom --toggle|--on|--off`; `move <PANE_ID> --tab|--split|--target-pane|--ratio|--new-tab`; `swap --direction|--source-pane|--target-pane`; `close <pane_id>` — required positional, no "current pane" fallback; `pane input --right-click herdr|pane` makes input routing an explicit per-pane property. Geometry is queryable (`layout`, `edges`, `neighbor`), so an agent can reason about space without screenshots.
Two asymmetries worth knowing: `pane report-agent --state` accepts only `idle|working|blocked|unknown` even though `done` is part of the detection vocabulary — **herdr separates observed state from self-reported state**; and the manual states *"a pane exists whether or not it contains an agent"*, with `agent start` requiring an existing available shell pane and **never creating, splitting or moving layout** — agent semantics and layout are deliberately separate layers. `report-agent` also takes a trailing `[RESUME_ARG...]`, the *"command that resumes this session after a Herdr restart"*. Its skill text further warns that ordinary CLI/API closes do **not** inherit the TUI's last-pane confirmation, and that a pane moved to another workspace receives a new ID while `previous_pane_id` still resolves only inside the moved process's inherited caller context.

**Whole `--default-config` read end to end (380 lines, 2026-11-08) — facts delta now cites:**
- **Input ownership follows the app's request, not focus.** `mouse_capture = true` captures clicks for herdr's own UI, and the comment is explicit that this is not exclusive: *"Pane apps like lazygit and btop can still receive mouse when they request it."* Same shape as `pane input --right-click herdr|pane`. This is the terminal-camp precedent for delta's rule that a foreign full-screen app gets the keyboard (and here the mouse) while chrome keeps a documented way in.
- **Machine-opened transient terminals do not touch the layout.** `[[keys.command]]` bindings have three `type`s: `shell` (detached, background), `pane` (*"opens a temporary pane and closes it when the command exits"*), and `popup` (*"opens a session-modal terminal without changing the tab layout"*) with `width`/`height` in **cells or percentages**. Precedent for delta's derived rule that windows opened *for an event* live in a layer, never in the human's split row.
- **Headless has a size, and attached clients override it**: `[server] headless_cols = 120`, `headless_rows = 40`, with *"Attached clients always use their own terminal size."* So the grid geometry of an unattached session is a declared setting, not an accident — relevant to delta's "agents run headless but everything is in a window" claim.
- **Scrollback is a byte budget, per pane, with a named rationale**: `scrollback_limit_bytes = 10000000` — *"Matches Ghostty's default scrollback-limit behavior."* One cap serves both the render-free background pane and the retained grid, which is the bound delta's window-sleep derivation needs.
- **Status has two vocabularies on purpose**: `status_indicators = "dots" | "symbols"`, symbols being *"distinct static glyphs for blocked, working, done, idle, and unknown states"* — note `done` and `unknown` exist in the *display* set while `report-agent --state` refuses `done`, which is the same observed-vs-self-reported split seen from the UI side. `agent_panel_sort = "spaces" | "priority"` (*"attention queue"*) is the sidebar's second ordering axis.
- **The sidebar rows are a token language, not a fixed layout**: `[ui.sidebar.agents].rows` is a list of lists of tokens — built-ins `state_icon, state_text, machine, workspace, tab, pane, agent, terminal_title, terminal_title_stripped` — plus **`$name` for values the pane reported through `report-metadata`**, per-token `fg`/`bold`/`dim`, `row_gap`, and a **`rows_by_agent` table that overrides the whole layout per agent id**. Spaces have their own token set (`state_icon, state_text, workspace, branch, git_status`). This is the concrete shape of "one authoritative location per fact" done as configuration.
- **Everything about bars and frames is a switch with its trade-off written inline**: `hide_tab_bar_when_single_tab`, `tab_bar_position = top|bottom`, `tab_bar_right` as an ordered list of `zoom|hostname|datetime|text|command` entries (resolved **on the server**, so they name the remote host), `window_title = "{hostname}: {workspace}"` with `{pane}`/`{tab}`/`{terminal_title}` and `{{`/`}}` escapes and the note that the title is rendered server-side, `pane_borders = "auto"|"always"|"off"`, `pane_outer_borders`, `pane_gaps`, `pane_scrollbars`, `sidebar_width/min/max`, `sidebar_start_collapsed`, `sidebar_collapsed_mode = compact|hidden`, `mobile_width_threshold = 64` (single-column layout below it), `confirm_close`, `prompt_new_tab_name`, `prompt_new_workspace_name`.
- **Restore after a server restart is a first-class session feature**: `[session] resume_agents_on_restore = true` — *"Resume supported AI-agent panes into their native conversation sessions after a Herdr server restart. Requires official integrations that report session refs"* — plus `startup_per_agent_delay_ms` to stagger restores. Pairs with `report-agent`'s trailing `[RESUME_ARG...]`.
- **IME handling is two separate opt-ins, and neither is the composition display**: `switch_ascii_input_source_in_prefix` (prefix mode only; on Windows it toggles a **Korean** IME between Hangul and English, other languages untouched; *"best-effort"*) and `reveal_hidden_cursor_for_cjk_ime`, which exposes the focused pane's cursor to the outer terminal *"so macOS input methods keep tracking the candidate window when TUIs paint their own cursor (Claude Code, pi, codex)"*, with `cjk_ime_agents` as an allow-list (its accepted names include `qodercli`, `qoder`, `opencode`, `claude`, `codex`, `gemini`, `kimi`, `qwen`, `maki`) and `cjk_ime_cursor_shape`. **Delta's own risk — where the composition string is drawn — is still not solved by either.**
- Smaller ones worth knowing: `update.channel = stable|preview` (the comment says stable builds default to `stable` and **Windows preview builds default to `preview`** so existing installs stay on it until switched), `manifest_check` fetches the agent-detection list remotely, `redraw_on_focus_gained` documents its own flash/corruption trade-off, `copy_on_select = false` retains selection *"until Ctrl+C, or Cmd+C when the host forwards it"*, `new_cwd = follow|home|current|<path>` for new panes/tabs/workspaces, `experimental.allow_nested`, `pane_history` (*"Save recent pane screen history across full server restarts"*), `[worktrees] directory`, `remote.manage_ssh_config` (herdr injects `ServerAliveInterval` + a private per-attach control socket **after** including `~/.ssh/config`, so user values win), and `advanced.scrollback_limit_bytes` living under `[advanced]`.

Two of its designs are the ones the user cared about most: agent lifecycle is **judged by watching the pane, not self-reported** — `idle|working|blocked|done|unknown`, where `blocked` means an approval or question dialog was recognized, and `agent explain` says why a state was inferred; and delivery has three separate acknowledgements, so `agent prompt --wait` fails with `agent_prompt_stalled` when nothing started working. `herdr agent start --kind` lists 21 agents (pi, claude, codex, gemini, cursor, devin, cline, opencode, copilot, kimi, qwen, hermes, amp, grok, …), and the kind list is refreshed by a remote manifest (`manifest_check`) rather than baked into the release. `herdr --skill` prints the agent-facing manual (usage plus behavioral safety rules), `herdr --default-config` prints the whole config schema. Keybindings distinguish `prefix+n` from direct chords like `ctrl+alt+n`; caller context arrives as `HERDR_ENV=1`, `HERDR_WORKSPACE_ID/TAB_ID/PANE_ID`; IDs are opaque (`w1:w1:p1`) and never reused.
