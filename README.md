一个 **AI terminal**。名字叫 Delta，不叫别的也不解释（*"我们叫Delta。不用管别人叫我们什么"*）。它是 kite/KKK 的后继设计。**2026-11-08 起准备写代码**（*"现在即将开始写代码"*），但**本目录只放文档**：代码与仓库要他点头才建。

这里放的是设计记录本身：法则、清单、证据、参考、未采纳的提案。Qoder 记忆里的同名条目是跨会话索引；**两者内容不一致时，以本目录为准**。快照日期 2026-11-08。

## 一句话的法则（详文见 laws/window-ownership.md）

1. 任务优先：任务在进行，窗口就不能关。绑住窗口的是这个任务当前的 output／事件（法则 10），一个窗口可以同时绑好几个，所以"不能关"是按**事件**计数，减到零才能关——**不是按任务计数**。
2. 只要是 AI 编辑的，就一定有一个窗口；pin 只在这次编辑在飞的期间。**删除例外：*"AI删除就删除呗，不显示"*** —— 删除不开窗口、不显示，唯一痕迹是法则 5 的自动 git/数据库，所以备份先行在这里是硬要求。
3. 窗口存在，AI 就接管——包括接管人类的窗口。
4. 读取不申请。**接管已存在的窗口就要申请，shell 和 editor 一视同仁，一次就行**；判据是**"这个窗口有没有被人类以非 agent、非 share 的形式在前台打开过"**——打开过就要重新授权（哪怕你一个字没改），没在前台打开过就不用。同意即自动保存并进入 agent。
5. 无论 AI 还是人类，操作都自动 GIT、自动数据库——数据库为权威，git 是产物。
6. terminal 知道 AI 在干什么，包括它建了什么文件。
7. 交接不限于编辑器：终端窗口同样交出去，人在旁边看它跑。
8. 事件必绑窗口；解耦后的窗口才能关；**停止住在事件调度器，不藏在关闭键里**。
9. 图层 + 窗口睡眠：有 z-order，下面的先不画，可随时切回。
10. AI output 只绑一个窗口；一个任务不绑它碰过的全部窗口。**一个窗口可以绑多个事件（*"3肯定允许啊。如果不允许的话，那软件不就没法写了吗"*）**，所以法则 1 的"不能关"按事件计数：绑定 +1，结束 −1，为零才可关。
11. AI 编辑的东西没有窗口，delta 就开一个（按路径幂等，优先接管已有）。
12. 窗口管理的**模式**已定；美学只学 tmux 与 ghostty，绝不学 kite。
13. 模式而非旗子：`normal / insert / replace / agent`，默认 normal，快捷键进入，ESC 退出，normal 是快捷模式；可执行由模式系统承载。**输入模式说的是键盘路由**：`insert` 就是把键原样交给 pane，所以外来全屏程序里 ESC 归那个程序，chrome 的退出键在那里是 prefix（推导，见 Derived answers）。
14. agent 模式的进入与退出只由 AI 决定。
15. share 是 AI 把人类请求进来的中间态：能输入，不能关，不能退；AI 实时看你的输入。
16. 模式有两个主语：输入模式属于键盘（只作用焦点窗口），归属模式属于窗口（无视焦点，决定能不能关）。
17. 群组是特殊窗口，没有这些状态。
18. agent 模式下人保住眼睛、失去键盘：该看的还是看，不能编辑。
19. 全屏程序原地开（tmux 的办法），但键盘必须真正转移，程序自己退出后窗口还在。
20. 自有编辑器：能力从 fresh / helix / nvim / vim / zed / vis 取，键位一个都不学，形态接近 `cat`。
21. **调度器和每个 AI 的实时流式信息是同一个窗口**：点开那个 AI 就是它，在那里关闭最好用（*"调度器与每个AI的实时流式信息是一个窗口"*)。调度器不另开一块面板。
22. **群聊也是一个窗口**：AI 任务可以在群聊里关，而**群聊关闭就是 AI 关闭**。
23. **界面上没有"工作区"这一层**：每个群聊开启时选一个工作区，那只是它的根路径；软件没有工作区面板、也没有对象树里的那一级（*"整个软件没有那个所谓的工作区"*）。
24. 名字：**编辑器 = `miku`，shell = `solid`**。
25. **solid 像 bash 但不是 bash**，只有基本内建（`cp md cd ls pwd` 等等），**`$` `@` 这类符号 shell 不用——留给 delta 自己的语法**（`@` 已经是群里的通信原语）。

**2026-11-08 由我推导并已写进法则、可推翻的一批**（每条都注明依据，见 `laws/window-ownership.md` 的 Derived answers 与 `laws/status-rollup.md` 第 55 条）：`replace` 是不是窗口级模式（**是**，输入模式=键盘路由状态，overtype 不是 vim 键位，所以与法则 20 不冲突）· 外来全屏程序的 ESC 归谁（**归那个程序**：`insert` 的定义就是键交出去，所以 chrome 的退出键在那里是 prefix，正是 tmux 只保留 prefix 的做法；并且**不抄 `escape-time`**）· 状态栏的 `insert` 与程序自己画的 INSERT（**两个事实，不需要调和**）· share 没人应答（**不要超时**，沿用 parked 那个形状：保留 pane 与身份、交出写权限、显示谁在等多久；出路只有群里说好了与调度器停止）· 法则 11 开出的窗口同时画几个（**不需要上限**：法则 9 只画最前，去处是图层栈，不进人类的分屏行——herdr `type=popup` 与 tmux 浮动面板都是这个先例）· 拒绝关闭去哪（**列出绑在这个窗口上的每一个事件，跳到调度器那一条**）· "还在干活"怎么判（**数活着的事件行／进程未退出，不数 `done`**）· 别人家程序在我们窗口里看不清楚容忍到哪（**显示尽力，权威绝不从外来 grid 取**）· 永不投票的 AI（**名单按 invited-and-live 算，停止即出名单，表决照样关窗**）· "执行必须发生在窗口里"（**不需要新法则**，可执行内容是"delta 只承认窗口里的执行"）。
